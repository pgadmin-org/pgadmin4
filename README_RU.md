# pgAdmin 4

pgAdmin 4 это переписанная версия популярного инструмента 
pgAdmin 3 для управления базами данных (http://www.postgresql.org).

В приведенной ниже документации и примерах используется *$PGADMIN4_SRC/* для
обозначения корневого каталога копии дерева исходного кода pgAdmin, полученного
 из архива tarball или путем клонирования репозитория git.

## Архитектура

pgAdmin 4 реализован как веб-приложение, использующее Python (Flask) на стороне 
сервера, а также ReactJS, HTML5 и CSS - для обработки на стороне клиента и построения 
пользовательского интерфейса.

Хотя pgAdmin 4 разработан с использованием веб-технологий, его можно развернуть 
либо на веб-сервере (с доступом через браузер), либо как самостоятельное приложение 
на рабочей станции. В подкаталоге runtime/ находится исполняемое приложение на 
базе Electron, обеспечивающее следующую возможность: приложение запускает серверный 
процесс на Python и отображает пользовательский интерфейс.

## Предварительные требования
1. Установите Node.js версии 20 или выше (https://nodejs.org/en/download);
2. Менеджер пакетов Yarn (https://yarnpkg.com/getting-started/install)
3. Python версии 3.9 или выше (https://www.python.org/downloads/)
4. Сервер PostgreSQL (https://www.postgresql.org/download)

Для начала включите Corepack, если он еще не включен -
это добавит исполняемый файл yarn в ваш PATH:
```bash
corepack enable
```

# Создание веб-ресурсов

pgAdmin зависит от ряда сторонних JavaScript-библиотек.
Их, наряду с собственным кодом JavaScript, CSS и изображениями, 
необходимо объединять в единый пакет "bundle", который передается 
в браузер для выполнения и отрисовки. Это гораздо эффективнее, чем 
запрашивать каждый ресурс отдельно по мере необходимости.

Для создания связки (bundle) необходимо, чтобы в  системе был установлен менеджер 
пакетов Yarn. После этого в *nix-системе можно выполнить следующие команды, чтобы 
загрузить необходимые пакеты и собрать связку (bundle):

```bash
$ cd $PGADMIN4_SRC
$ make install-node
$ make bundle
```

На системах Windows (где команда "make" недоступна), можно использовать следующие команды:

```
C:\> cd $PGADMIN4_SRC\web
C:\$PGADMIN4_SRC\web> yarn install
C:\$PGADMIN4_SRC\web> yarn run bundle
```

# Настройка среды Python

Для выполнения кода на Python необходима подходящая среда исполнения. 
В настоящее время поддерживаются версии Python 3.9 и выше. Для этой цели 
рекомендуется создать виртуальную среду Python, а не использовать системную 
среду. В системах Linux и macOS этот процесс довольно прост - при необходимости 
адаптируйте его под свой дистрибутив:

1. Создайте виртуальную среду в подходящем каталоге. 
Последний аргумент это - имя окружения; его можно изменить по своему усмотрению:

   ```bash
   $ python3 -m venv venv
   ```

2. Теперь активируйте виртуальную среду:

   ```bash
   $ source venv/bin/activate
   ```

3. Некоторые компоненты, которые использует pgAdmin, требуют очень свежей версии *pip*, 
поэтому обновите его до последний версии:

   ```bash
   (venv) $ pip install --upgrade pip
   ```

4. Убедитесь, что каталог bin/ установленного PostgreSQL добавлен в переменную 
окружения PATH (чтобы утилита pg_config была доступна для сборки psycopg3), и установите 
необходимые пакеты:

   ```bash
   (venv) $ PATH=$PATH:/usr/local/pgsql/bin pip install -r $PGADMIN4_SRC/requirements.txt
   ```

   Если вы планируете проводить регрессионное тестирование, вам также 
   необходимо установить дополнительные зависимости из web/regression/requirements.txt:

   ```bash
   (venv) $ pip install -r $PGADMIN4_SRC/web/regression/requirements.txt
   ```

5. Создайте локальный файл конфигурации для pgAdmin. Отредактируйте
   $PGADMIN4_SRC/web/config_local.py и добавьте необходимые параметры конфигурации
   (используйте файл config.py как образец - любые настройки продублированные в
   config_local.py переопределят соответсвующие параметры из config.py). Типичная 
   конфигурация для разработки может выглядеть следующим образом:

    ```python
   import os
   import logging

   # Изменить каталог данных pgAdmin
   DATA_DIR = '/Users/myuser/.pgadmin_dev'

   # Изменить сервер и порт в pgAdmin
   DEFAULT_SERVER = '127.0.0.1'
   DEFAULT_SERVER_PORT = 5051

   # Переключение между десктопным и серверным режимами
   SERVER_MODE = True

   # Измените путь к базе данных конфигурации pgAdmin, если используется внешняя база данных.
   CONFIG_DATABASE_URI="postgresql://postgres:postgres@localhost:5436/pgadmin"

   # Настройка протокола SMTP
   MAIL_SERVER = 'smtp.gmail.com'
   MAIL_PORT = 465
   MAIL_USE_SSL = True
   MAIL_USERNAME = 'user@gmail.com'
   MAIL_PASSWORD = 'xxxxxxxxxx'

   # Изменение уровня логирования
   CONSOLE_LOG_LEVEL = logging.INFO
   FILE_LOG_LEVEL = logging.INFO

   # Используйте отдельную базу данных конфигурации для каждого режима работы сервера
   if SERVER_MODE == False:
     SQLITE_PATH = os.path.join(
         DATA_DIR,
         'pgadmin4-desktop.db'
     )
   else:
     SQLITE_PATH = os.path.join(
         DATA_DIR,
         'pgadmin4-server.db'
     )
   ```

   Это конфигурация поддерживает простое переключение между серверным и десктопным режимами,
   для тестирования.

6. Первоначальная настройка базы данных конфигурации выполняется в интерактивном режиме 
на сервере и в неинтерактивном десктопном режиме. Вы можете запустить ее, выполнив одну из 
следующих команд:

   ```bash
   (venv) $ python3 $PGADMIN4_SRC/web/setup.py
   ```

   or by starting pgAdmin 4:

   ```bash
   (venv) $ python3 $PGADMIN4_SRC/web/pgAdmin4.py
   ```

Хотя программу установки можно автоматически запустить в десктопном режиме путем 
запуска среды выполнения (runtime), в серверном режиме это не сработает, так как 
среда выполнения не поддерживает взаимодействие с программой установки через командную 
строку.

Теперь вы сможете запустить pgAdmin 4 из командной строки в серверном или десктопном режиме 
и получить к нему доступ через веб-браузер, используя URL-адрес, который отобразится в 
терминале после запуска pgAdmin.

К сожалению, настройка среды в Windows несколько сложнее, пожалуйста смотрите 
*pkg/win32/README.md* для получения полной информации.

# Сборка документации

Для сборки документации в виртуальной среде требуется дополнительный пакет Pyhton.
Его можно установить с помощью менеджера пакета pip:

```bash
$ source venv/bin/activate
(venv) $ pip install Sphinx
(venv) $ pip install sphinxcontrib-youtube
```

Затем документацию можно собрать с помощью "Makefile" в *$PGADMIN4_SRC*, например:

```bash
(venv) $ make docs
```

Результат можно найти в файле *$PGADMIN4_SRC/docs/en_US/_build/html/index.html*

## Сборка среды выполнения
Перейдите в каталог среды выполнения и выполните команду *yarn install*.
Это установит необходимые зависимости.

Для использования среды выполнения (runtime) в среде разработки необходимо скопировать файл
*dev_config.json.in* в *dev_config.json*, и отредактировать пути к исполняемому файлу Python 
и файлу *pgAdmin.py*, в противном случае среда выполнения будет использовать пути по умолчанию, 
предусмотренные для стандартного пакета под вашу платформу.

Затем вы можете запустить среду выполнения, выполнив команду в виде:

```bash
yarn run start
```

# Сборка пакетов

Большинство пакетов можно собрать с помощью "Makefile" в $PGADMIN4_SRC, при условии 
выполнения всех описанных действий выше, по настройке и конфигурированию.

Собрать исходный tar-архив:

```bash
(venv) $ make src
```

Чтобы собрать PIP-пакет (Wheel), активируйте виртуальное окружение Python 3, 
настроенное со всеми необходимыми пакетами, а затем выполните:

```bash
(venv) $ make pip
```

Инструкции по сборке AppBundle для macOS см. здесь: *pkg/mac/README.md*.

Для сборки установщика Windows см. здесь: *pkg/win32/README.md*.
# Создание миграций базы данных

Чтобы внести изменения в базу данных SQLite, перейдите в каталог "web":

```bash
(venv) $ cd $PGADMIN4_SRC/web
```

Создайте файл миграции с помощью следующей команды:

```bash
(venv) $ FLASK_APP=pgAdmin4.py flask db revision
```

Это создаст файл в $PGADMIN4_SRC/web/migrations/versions/ .
Внесите все изименения в функцию `upgrade`.
Увеличьте значение SCHEMA_VERSION в файле $PGADMIN4_SRC/web/pgadmin/model/__init__.py.

Нет необходимости увеличивать SETTINGS_SCHEMA_VERSION.

# Вопросы безопасности

Если вы хотите сообщить о проблеме безопасности в pgAdmin, пожалуйста свяжитесь по адресу
**security (at) pgadmin (dot) org**.

Обратите внимание, что этот адрес следует использовать только для сообщения о проблемах безопасности, 
обнаруженных по вашему мнению, в архитектуре или коде pgAdmin, pgAgent и веб-сайта pgAdmin. Его не 
следует использовать для вопросов, касающихся безопасности.
